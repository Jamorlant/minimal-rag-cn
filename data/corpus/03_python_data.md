# Python 数据处理手册

## 环境与依赖

建议使用虚拟环境隔离依赖，通过 python -m venv .venv 创建，激活后再执行 pip install，避免污染系统环境。

依赖版本应写入 requirements.txt 并固定主版本号，防止上游升级导致接口变化。

在脚本开头显式声明编码 utf-8，读写中文文件时避免平台默认编码带来的乱码问题。

日志优先使用 logging 模块而不是 print，配置级别和格式后可以同时输出到控制台与文件。

## 列表与字典操作

列表推导式比 for 循环加 append 更快，同时可读性更好，但嵌套超过两层时建议改为普通循环。

enumerate 同时获取下标与元素，zip 可并行遍历多个序列，两者都比手写索引更简洁。

字典的 get 方法可提供默认值，避免键不存在时抛出 KeyError。

collections.Counter 用于计数统计，most_common(n) 可直接返回频次最高的 n 个元素。

collections.defaultdict 在访问不存在的键时自动创建默认值，适合分组聚合。

字典按键排序可用 sorted(d.items(), key=lambda x: x[1], reverse=True)，值为可比较类型时可直接排序。

浅拷贝只复制外层容器，内部可变对象仍共享引用；深拷贝需要 copy.deepcopy，代价更高。

## 文件读写

文本文件用 with open(path, encoding='utf-8') as f 打开，上下文管理器保证异常时也能关闭文件。

大文件逐行迭代而不是 readlines 一次性读入，可把内存占用从 O(n) 降到常数级。

CSV 读写优先使用 csv 模块或 pandas，手工 split 逗号无法处理字段内含逗号或换行的情况。

JSON 序列化用 json.dumps，中文需要设置 ensure_ascii=False 才能保留可读字符。

JSON Lines 每行一个对象，适合流式处理大文件，读取时逐行 json.loads 即可。

路径拼接使用 pathlib.Path，避免手写斜杠在 Windows 与类 Unix 系统上的差异。

写入文件前先写临时文件再原子替换，可以避免程序中断留下半截内容。

## pandas 基础

DataFrame 是带标签的二维表格，Series 是带标签的一维数组，索引是两者的对齐基础。

read_csv 常用参数包括 sep、encoding、dtype、usecols、na_values，提前指定 dtype 可避免后续类型推断错误。

查看数据先用 head、info、describe，info 能快速发现缺失值与类型异常。

loc 按标签选取，iloc 按位置选取。链式赋值可能不生效，应使用一次性赋值或 assign。

缺失值处理包括 dropna 删除、fillna 填充、interpolate 插值，选择哪种取决于缺失比例与业务含义。

groupby 后使用 agg 可对多列做多种聚合，agg 传入字典即可为每列指定不同函数。

merge 类似 SQL 的 join，how 参数支持 inner、left、right、outer，连接键类型不一致会导致匹配失败。

concat 用于纵向或横向拼接，axis=0 纵向追加，ignore_index=True 可重置索引。

pivot_table 生成透视表，index 为行维度，columns 为列维度，aggfunc 指定聚合方式。

apply 逐行或逐列调用函数，灵活性高但比向量化慢，能用内置方法时优先向量化。

向量化运算比循环快一到两个数量级，字符串批量处理可用 Series.str 访问器。

to_datetime 可统一解析日期，解析失败时用 errors='coerce' 把异常值转为 NaT 便于统计。

设置和重置索引用 set_index 与 reset_index，多级索引可用 droplevel 删除某一层。

排序使用 sort_values，多列排序传入列表，ascending 可传布尔列表分别控制升降序。

去重使用 drop_duplicates，subset 指定参与比较的列，keep 控制保留第一条还是最后一条。

## numpy 基础

ndarray 是同类型元素的多维数组，相比列表具有更低的内存开销和更快的向量化运算。

创建数组常用 np.array、np.zeros、np.ones、np.arange、np.linspace，指定 dtype 可控制精度。

广播机制允许不同形状的数组参与运算，规则是从尾部维度对齐，维度为 1 可自动扩展。

切片返回视图而非副本，修改视图会影响原数组，需要独立数据时调用 copy。

reshape 改变形状但不改变数据顺序，-1 表示由剩余元素推断该维长度。

矩阵乘法用 @ 或 np.dot，逐元素乘法用 *，两者语义不同不可混用。

统计函数 axis=0 表示按列聚合，axis=1 表示按行聚合，返回维度会减少一维。

np.where 可实现向量化条件判断，等价于三元表达式但速度更快。

随机数通过 np.random.default_rng(seed) 创建生成器，固定种子保证实验可复现。

## Excel 处理

openpyxl 读取工作簿用 load_workbook(path, read_only=True, data_only=True)，只读模式内存占用更低。

data_only=True 读取的是 Excel 缓存的公式结果，若文件从未被 Excel 打开过则可能为 None。

写入大数据量时使用 write_only 模式并逐行 append，可显著降低内存峰值。

单元格格式包括字体、填充、对齐、边框与数字格式，批量设置应复用样式对象。

合并单元格后只有左上角保存值，读取时其余单元格为 None，需要向下填充补齐。

pandas 的 to_excel 支持多工作表，通过 ExcelWriter 上下文管理器一次写入多个 DataFrame。

工作表名长度不能超过 31 个字符，且不能包含斜杠、方括号等非法符号。

## 异常与健壮性

捕获异常应指定具体类型，不要使用裸 except，否则会吞掉键盘中断和程序错误。

自定义异常继承 Exception 并携带上下文信息，便于上层按类型分流处理。

finally 块用于释放资源，即使发生异常也会执行。

重试机制适合处理网络抖动，应设置最大次数与退避间隔，避免无限重试拖垮服务。

批量任务中单条失败不应中断整体，记录失败明细后继续处理，最后统一汇总。

## 性能与内存

使用生成器处理大数据可避免一次性载入内存，yield 逐个产出结果。

避免在循环内做重复计算，把不变的部分提到循环外。

字符串格式化在大量拼接时优先用 join 或 f-string，减少中间对象创建。

内存分析可用 tracemalloc 或 memory_profiler，定位占用最高的对象后再优化。

多进程适合 CPU 密集型任务，多线程适合 IO 密集型任务，受 GIL 限制线程无法并行执行 Python 字节码。

## 类型注解与工程质量

类型注解不会在运行时强制校验，但配合静态检查工具可以在提交前发现大量潜在错误。

Optional 表示可为 None，函数返回值应显式声明 Optional 而不是隐式放行 None。

typing 的 Protocol 支持结构化子类型，适合描述「只要有某个方法即可」的鸭子类型接口。

dataclass 自动生成初始化、比较与打印方法，比手写类更简洁，field 可设置默认值与是否参与比较。

枚举 Enum 用于限定取值集合，避免字符串魔法值在代码中随意扩散。

类型检查用 mypy 或 pyright，严格模式下需要为外部库准备类型存根。

## 数据清洗实战

空字符串与 NaN 语义不同，统计缺失时先统一为 None 再判断，避免把空串当作有效值。

手机号与证件号属于敏感信息，展示与导出时应脱敏，仅保留必要片段。

日期字段常见问题有字符串格式混杂与单位不统一，统一转换为 datetime 后再比较。

重复记录判定需要业务主键，仅按全部字段比较会把合法的近似记录误删。

异常值处理应先确认是录入错误还是真实业务极值，盲目删除会扭曲分布。

字段类型转换失败的行应单独输出到失败清单，便于人工复核而不是静默丢弃。

## 时间序列处理

重采样用 resample 按天、周、月聚合，需指定聚合函数与缺失时段的填充策略。

时区转换用 tz_localize 标注原始时区，再用 tz_convert 转换到目标时区，顺序颠倒会报错。

移动平均用于平滑短期波动，窗口越大越平滑但滞后越明显。

同比需要按日历对齐，跨年与闰年会带来天数差异，按月份对齐比按天数偏移更稳妥。

时间序列缺失可用前向填充或线性插值，长期缺失应标记而不是强行补齐。

统计周期边界要明确是否包含右端点，开区间与闭区间会导致临界数据重复或遗漏。

## 图表与输出

matplotlib 中文字体需要显式设置，否则会出现方块乱码。

柱状图适合比较类别，折线图适合展示趋势，饼图类别过多时难以辨识应改用条形图。

坐标轴截断会夸大差异，起点为零还是自动缩放需要在图注中说明。

图表标题与单位要完整，仅靠图例无法让读者理解口径。

导出图片时提高 DPI 可避免模糊，但文件体积会同步增大。

交互式图表适合探索，正式报告应导出静态图以保证可复现。

## 测试与可维护性

pytest 用 test_ 前缀识别用例，断言失败会输出实际值与期望值的差异。

参数化测试用 parametrize 覆盖多组输入，避免复制粘贴大量相似用例。

fixture 用于准备共享数据与清理临时文件，scope 控制创建频率。

测试应覆盖边界值、异常分支与幂等性，只测正常路径容易漏掉线上问题。

随机性测试需固定种子，否则失败时无法稳定复现。

覆盖率不等于质量，关键分支的断言是否有效比百分比更重要。

## 日志与可观测性

日志格式包含时间、级别、模块与消息，结构化日志便于后续检索与统计。

异常日志应记录堆栈与上下文，重复的错误可用采样避免日志淹没。

耗时统计可在函数入口与出口打点，也可用装饰器统一封装。

关键业务指标应上报到监控系统，日志仅作补充证据。

敏感字段进入日志前需脱敏，包含令牌与个人信息的日志属于高风险数据。

## 批处理任务组织

批处理按批读取、按批写入，批大小需要根据内存与接口限流共同确定。

失败重试应记录已处理游标，避免整批重跑造成重复写入。

任务需要支持断点续跑，状态保存到文件或数据库，重启后从上次位置继续。

并发处理时注意下游接口的速率限制，可用信号量或令牌桶控制并发度。

任务结束输出统计摘要，包括成功条数、失败条数与耗时，便于快速验收。

中间文件使用临时目录并在结束后清理，避免长期占用磁盘。

## 代码组织与复用

模块按职责划分，数据读取、清洗、业务计算与输出应彼此独立。

公共逻辑抽取为函数时优先保持纯函数，输入输出明确，便于测试。

避免过深的嵌套，提前返回可以让主流程更清晰。

配置与常量集中管理，散落在各处的魔法数字难以维护。

异常在合适的层次捕获，底层只抛出，由业务入口统一处理并给出可读提示。

代码评审关注命名、边界与错误处理，格式问题交给工具自动处理。

## 大数据量的内存控制

读取千万行级的 CSV 时，先指定 dtype 与 usecols 能把内存占用压到原来的三分之一。

分块读取用 chunksize 参数返回迭代器，每块处理完即可释放，适合无法整体载入的数据。

把字符串列转换为 category 类型，在取值重复度高时可大幅降低内存占用。

及时删除不再使用的中间 DataFrame 并调用 gc.collect，能缓解内存峰值压力。

避免不必要的 copy，pandas 的很多操作默认返回新对象，链式调用会累积大量临时对象。

导出时按行流式写出比一次性构造大对象更安全，尤其是需要拼接格式化字符串的场景。

对超大数据可先聚合再明细，报表只需要汇总值时不必保留全部原始行。

## Excel 复杂场景

多表关联的数据常用「一表一文件」的组织方式，批量读取时按文件名解析业务日期与区域。

公式结果为空值的情况要区分「未计算」与「计算结果为空」，前者需要先用 Excel 打开并保存。

合并单元格读取后需要向下填充，但填充会改变原始行数，统计前要还原真实粒度。

日期在 Excel 中以序列号存储，用 openpyxl 读取时可能是数字，需要按单元格格式转换。

图表与透视表不属于单元格数据，pandas 无法读取，需要单独用 openpyxl 处理对象层。

文件被其他进程占用时写入会失败，应先检测锁文件或提示用户关闭。

保存前设置只读推荐与保护密码可以防止误改，但不能替代权限管理。

## 命令行与配置

argparse 适合构建带子命令的工具，每个子命令各自定义参数，帮助信息自动生成。

参数默认值应来自配置文件或环境变量，命令行只做覆盖，避免每次运行都传一长串参数。

路径参数要处理相对路径与绝对路径，统一用 Path 解析并在日志中打印最终路径。

布尔参数用 store_true 形式，避免用户还需要额外传值。

退出码用于区分成功与失败，脚本失败时返回非零值便于调度系统判断。

标准输出用于结果，标准错误用于日志与警告，混在一起会让管道处理出错。

## 虚拟环境与依赖

requirements.txt 适合固定直接依赖，锁文件则记录完整的传递依赖树。

生产环境应使用锁定版本，避免上游小版本升级引入行为变化。

安装失败时先看是否缺少编译工具，纯 Python 包通常不受影响。

国内网络环境下可配置镜像源，但要注意镜像同步延迟导致的版本不一致。

依赖冲突可用 pip check 检测，升级单个包前先评估影响范围。

开发依赖与运行依赖分开声明，避免把测试框架装进生产镜像。

## 数据校验与质量检查

字段级校验检查非空、类型、长度与取值范围，跨字段校验检查业务约束，例如结束时间必须晚于开始时间。

行数校验用于发现抽取阶段的数据丢失，可对比源表与目标表的记录总数，并允许按已知规则设定差异阈值。

主键唯一性校验是去重与关联正确性的基础，重复主键往往意味着上游合并逻辑存在问题。

金额校验要求明细之和等于汇总值，差额超过阈值时应阻断后续流程并保留现场数据。

时效校验检查最新数据的时间戳是否在预期窗口内，延迟超过阈值说明上游任务异常。

校验结果需要留痕，记录校验时间、样本与结论，便于复盘时还原当时的判断依据。

校验失败的处理策略分阻断与告警两类，影响对外口径的应阻断，仅影响体验的可在告警后继续。

## 数据入库与对接

入库前统一字段命名与类型，避免同一含义在多个表中使用不同名称导致关联困难。

批量写入时按主键去重或使用更新插入语义，保证重复执行不会产生重复数据。

事务范围应尽量小，长事务会持有锁并阻塞其他写入，影响整体吞吐。

写入失败要记录原始行内容与错误原因，便于离线修复后重放。

增量同步依赖更新时间戳时要考虑时钟偏差，同时使用主键范围做兜底。

数据库连接应使用连接池并设置合理的最大连接数，连接泄漏会导致服务逐渐不可用。

敏感数据入库前完成脱敏或加密，密钥与数据分开存放。

## 数据看板与口径沟通

看板上的每个指标都要能追溯到计算逻辑与数据来源，否则争议时无法自证。

指标定义变更需要版本记录，历史数据与新口径混用会造成趋势断裂。

看板加载性能依赖查询效率，常用手段有预聚合、缓存与增量刷新。

筛选条件应默认给出明确值，留空容易让使用者误读为全量。

异常值展示要标注原因，直接隐藏会让使用者怀疑数据缺失。

使用说明放在看板显眼位置，减少重复解释的成本。
